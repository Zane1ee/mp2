  两个入口各 10 分，Previous/Next 10 分，不能等到最后再连接详情页。

  不为账号、收藏、登录、进化树、无限滚动或复杂动画扩大第一版范围。
- 主要风险：API 请求扇出、乱序响应、缺字段/缺图、排序原地修改数组、

STEP 4: MAP REQUIREMENTS TO THE THREE VIEWS
------------------------------------------------
Actions:
  A. LIST VIEW（信息检索页；28 分）
    - 构成：页面标题/范围说明、带 label 的搜索框、排序属性选择器、独立
      Ascending / Descending 控件、结果数量、语义列表、加载/空/错误状态。
    - 推荐每行显示：名称、编号、小图、已加载时的类型；整条主链接去详情。
    - 两个排序属性：Name（文本）与 Number / ID（数值）。两者均支持
      A→Z / Z→A 或小→大 / 大→小；名称并列时用 ID 稳定决胜。
    - 输入变化立即过滤名称，大小写不敏感、忽略首尾空格；清空恢复完整
      的已批准目录。无需回车、提交按钮或每个按键一次 API 请求。
    - 排序作用于全部匹配对象，不只作用于当前可见的一小块。

  B. GALLERY VIEW（以图像为主的浏览页；12 分）
    - 构成：标题/范围说明、类型多选、Clear filters、结果数量、图片网格、
      卡片名称/编号/类型、加载/空/错误状态。
    - 图片来自所选 API 的响应媒体字段；不能以装饰背景或自制卡通图
      代替评分要求的 item media。缺图可显示可访问的占位提示。
    - 推荐 Pokemon types 多选；选择 fire / water 等实际存在的属性会
      改变网格内容。空选择代表 All；多选 OR 逻辑见 STEP 7 / D5。
    - 卡片链接进入与 List 共用的详情 route，而不是另做图库专属详情。

  C. DETAIL VIEW（可分享的对象页；38 分）
    - 构成：返回来源视图链接、名称/编号、大图、类型、身高/体重、能力
      名称、基础 stats、Previous / Next、当前集合内位置及错误状态。
    - 本 SOP 建议这些属性；README 只要求不同 item details，未规定字段数。
    - route 推荐 /pokemon/:id；URL 里的稳定 ID 是主身份，不能依赖刚才
      点击的卡片对象、数组下标或临时 location.state 才能渲染。
    - Previous/Next 使用进入详情时那份过滤且排序后的集合；直接 URL
      访问使用默认目录顺序。具体边界语义见 STEP 7 / D5。

Verify:
  - 三个 view 是同一 React SPA 的三个页面，不是一个页面上三个假标签。
  - 实时搜索、图库属性过滤、两个入口、完整详情、前后导航各有独立验收。
  - 详情不是只有图片/标题的模态框，且地址栏确实出现对象专属 URL。

STEP 6: PREPARE THE API, ENVIRONMENT AND SOURCE MANIFEST
------------------------------------------------
Actions:
  - 推荐 API 契约（D1/D4 采用推荐值时）：
      Base URL: https://pokeapi.co/api/v2/
      Catalog:  GET pokemon?limit=60&offset=0（再检查/限定 ID 1-60）
      Detail:   GET pokemon/<id>/
      Required mapping: id, name, types[].type.name, sprites.front_default,
                        height, weight, abilities[].ability.name, stats[]
      图片先用实际响应里可用的图像字段，允许 sprites 的嵌套图作为增强；
      不仅凭猜测拼接第三方图片地址。height / 10 → m，weight / 10 → kg。
  - 内部对象统一 ID 为 number，姓名/类型为字符串，imageUrl 可为 null；
    数值缺失显示 "Unavailable"，不补造评分、身高、能力或编号。
    请求层验证关键字段与 ID，TypeScript 类型本身不验证网络 JSON。
  - 开发前 API 可用性校验计划：浏览器从 localhost 发出少量实际请求，
    检查 JSON、CORS、HTTPS 图片、类型样例和缺图处理；线上再做同样检查。
    第 1 轮真实浏览器请求/图片已通过；实际 GitHub Pages 访问尚未验证。
  - 请求预算：推荐目录冷启动最多 1 次目录 + 60 次详情（不含图片，
    不含明确重试）；详情请求最多 4 个并发。不一次 Promise.all 打满 60。
    详情与图库共用缓存，搜索/排序/过滤不再请求整份目录。
  - PokéAPI 文档当前说明免认证且无常规限流，同时要求节制并缓存请求。
    通用错误流程仍处理 429 / 网络失败；不能据此进行无限并发或重试。
  - 必需环境：Node/npm、可安装依赖的网络、浏览器、已存在的 GitHub 仓库。
    必需项目工具：React、TypeScript、React Router、Axios、Vite react-ts。
    推荐 normalize.css + CSS Modules；不需要 Python、Docker、数据库。
  - MCP：README 未要求任何 MCP。现有浏览器操作能力可用于验收；没有
    专用浏览器 MCP 时也可手动检查。GitHub API/CLI/连接器用于读部署状态
    是便利工具，Drive 连接器用于上传是便利工具，均不阻塞本地代码。
    本轮不安装插件、不连接账户；实际分享、上传或消息另按当时授权执行。
  - 采用 PokéAPI 时无需 .env/key。换成需要 key 的 API 时，只用免费接口；

STEP 7: SPECIFY INTERACTION AND STATE BEHAVIOR BEFORE CODING
------------------------------------------------
Actions:
  - List：query 为受控输入；trim + 大小写归一化，名称 substring 匹配；
    空字符串匹配全部。两种 sortKey 与两种 direction 是合法枚举。
    数字排序不得按字符串排序；用副本排序，不原地修改共享目录。
  - Gallery：type 候选来自批准目录的已验证数据；选中列表去重。
    推荐 selectedTypes 为空时全保留，否则 item.types 中任一类型命中。
    取消一个选项、清空、多选均应立刻改变结果；顺序默认按 ID 升序。
  - 加载：名单与 name/ID 就绪后 List 可用；类型/图片数据继续加载。
    Gallery 属性筛选等类型索引完整后才开放，显示加载进度。某项失败时
    显示失败数/重试，不把未知类型当成“没有匹配”，也不显示假零结果。
    进入某个详情时优先取该项缓存或请求，不必等待全部目录下载完。
  - URL：List / Gallery 的查询条件用 search params 保存，外部输入先校验。
    List 例：/list/?q=bulb&sort=name&order=asc
    Gallery 例：/gallery/?type=fire&type=water
    Detail 例：/pokemon/1/?from=list&q=bulb&sort=name&order=asc
    路径均为相对 Router base 的路径；线上前面再加 /mp2。
  - Detail 的 orderedIds：
      1. from=list：重建相同 query/sort/direction 的全部匹配 ID。
      2. from=gallery：重建相同 types 的全部匹配 ID，按 ID 升序。
      3. 无来源：批准目录按 ID 升序；ID 必须从 route 获取。
    不只用某个显示分块，不用“ID + 1”代替过滤集合中的下一项。
  - 推荐循环：第一个 Previous 到末项，末项 Next 到首项；一项时禁用
    两端；空集合没有可点项。若当前 ID 不属于 URL 来源集合，则展示该
    项并注明改用默认目录顺序，不做 index=-1 运算或静默崩溃。
    ID 非法/不在批准范围时显示清楚的 Not found / Out of catalog 和返回。
  - Next/Previous 更新 route ID，同时保留来源条件；刷新可重建；返回
    来源用明确 Link，不只 navigate(-1)，避免直达 URL 没有返回历史。
  - API 状态：idle/loading/success/error 分开；未加载不显示“0 results”。
    快速切 ID 的旧响应不能覆盖新 ID；取消请求不作为用户错误提示。
    React StrictMode 的开发 effect 重跑通过清理/请求去重处理。
  - live/sample 若并存，URL 标注模式并隔离缓存及 orderedIds；重试不会
    把两套数据无声混合。样例范围与实时范围分别明确标注。

Verify:
  - 两个来源、直接进入、刷新、后退/前进都能得出确定且一致的详情序列。
  - 单项、空结果、双属性四组合、OR 多选、非法 query/ID 均有明确行为。
  - 不依赖刷新后丢失的内存导航状态，也不依赖数据下载完成先后决定顺序。
